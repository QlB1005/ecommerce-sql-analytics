\# 数据说明



本仓库\*\*不包含业务数据\*\*。分析 SQL 基于导师商业项目中的电商表结构编写；结论数字来自该项目一次跑数，不随仓库分发。



\## 主要用到的表



| 表名 | 用途 |

| --- | --- |

| user\_master | 用户、注册时间、渠道、设备 |

| user\_login\_log | 登录流水，用于留存 |

| product\_category | 商品分类 |

| product\_detail | 商品、品牌、售价、成本 |

| order\_master | 订单、支付状态、金额、时间 |

| order\_detail | 订单明细、数量、是否退货 |

| payment\_record | 支付方式与支付结果 |

| traffic\_log | 浏览 / 流量 |

| user\_behavior\_event | 加购等行为事件 |

| shopping\_cart | 购物车（本项目分析未作为主表） |



\## 统一口径



\- 时间窗口：截止日 `2026-03-17`，往前 90 天

\- 支付成功：`payment\_status = 'PAID'`

\- LTV：客单价 × 毛利率 × 人均购买频次 × 渠道转化率（转化率为渠道级）

\- RFM 的 M：按销售额从高到低累计贡献切分，不是按人数前 20%

\- 漏斗：浏览之后 7 日内的加购 / 下单 / 支付



\## 使用方式



1\. 在自己的 MySQL 中执行 `sql/00\_schema/schema.sql` 了解表结构

2\. 阅读并运行 `sql/01\_metrics`、`sql/02\_ltv`、`sql/03\_rfm`、`sql/04\_funnel`

3\. 若无数据，SQL 仅用于阅读口径与写法，结果不会与 README 中的数字一致
