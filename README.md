# 电商经营分析（90天指标 / 渠道产出 / 用户分层 / 转化漏斗）

老师给定真实商业数据，我用 SQL 先对齐支付和时间口径，再在同一窗口上做渠道贡献 ROI、货盘主推、RFM、漏斗；FineBI 看渠道支付用户与窗内复购。投放和选品分开：加停降只看渠道，主推看渠道 × 品牌。

>本仓库只放表结构和分析 SQL，不含业务数据和数据库账号。文中数字来自该项目一次跑数（截止 2026-03-17）。

## 总结论
在同一套已支付订单、同一窗口（2025-12-17～2026-03-17）上，同时回答四件事：
1. **口径：** 成交只算 `paid`；GMV 打订单头，货本打明细。后面三节都用这一套。
2. **投放与货盘：** 停投抖音、京东；淘宝降费，主推品牌 C、B，A 作利润款；拼多多维持，主推无品牌；微信不投信息流，私域推品牌 A、B、C。窗内贡献约 2.7 万，约占 GMV 的 9%。
3. **用户分层：** 普通客户约占 81% 人、74% 金额；重要保持约占 15% 人、17% 金额；VIP 约占 4% 人、9% 金额。优先对重要保持做复购。
4. **漏斗：** 浏览→加购约 35.9%，加购→下单约 43.7%，下单→支付约 83.0%。人主要流失在前两步；对应2的个渠道主推方案，暂不加投放修漏斗。
5. **看板：**搭建渠道与用户看板，合并渠道支付用户、窗内复购、周趋势、月度支付用户数与设备，替代原每周 4 小时的手工统计，识别出春节带来的周趋势波动并且明确看渠道要把支付用户数与复购一起看。

## 1. 口径：先对齐，后面才能比

### 结论
先划分状态，再算指标。成交只统计 `paid`；整单退是 `refunded`，不进 GMV；部分退留在 `paid` 上用 `refund_amount` 扣。分析窗统一为 2025-12-17～2026-03-17，后面的渠道 ROI、RFM、漏斗都用这一窗。
### 证据 / 做法

#### 支付状态机
- unpaid：下了单没付款，不算成交
- paid：钱还在店里，可含部分退
- refunded：整单退光，GMV 和单数都不要

#### 指标落表
- GMV、佣金、用户运费、店铺运费、部分退：只打 `order_master`
- 货本、件数、是否退货：打 `order_detail`，货本只计 `is_return = 0`
- 渠道：注册渠道 `user_master.channel_source`
- 禁止：join 明细后再 `sum(payment_amount)`，一单多件会把实收加多遍
- 支付状态统一写 `paid`，时间统一用 `order_time`，漏斗浏览用 `view_time`


### 建议
- 第 2、3、4 节都建立在这套状态机上：成交 = paid，同一时间窗

指标 SQL 见 `sql/01_metrics/`。

## 2. 渠道ROI和主推品牌
投放（停 / 降 / 维持）只看渠道贡献 ROI；主推什么货看渠道 × 品牌。
提出 6 条渠道调整建议，其实4条被业务方采纳执行

### 结论  
- 淘宝建议做降费处理后续主推品牌BC，品牌A可作为利润款
- 拼多多维持原来投放后续可主推无品牌，品牌A可做利润款，少推品牌B
- 抖音和京东停止投放
- 微信属于私域无需投放后续主推品牌为ABC


### 证据 / 做法 

#### 淘宝：
- 贡献为正；贡献 ROI 0.20；费比约 30%偏贵；ROAS 3.36；货毛利率 46.5%
即渠道能留，广告偏贵建议降费
- 货盘：
- 单量>30
- 品牌A、B、C单量分别为 165、212、211 BC 为渠道头部 A可当利润款
- 品牌B、C 的毛利贡献为15813.6604、16624.3615 相差不大 可并列最高
- 品牌B、C的退货率分别为0.0369、0.0228
- 所以主推款可以为品牌C 或BC


#### 拼多多:
- 贡献为正但薄；贡献 ROI 0.08；费比约 24%可接受；ROAS 4.02；货毛利率 38.8%较薄即能留走量，保持
- 货盘：
- 单量>30
- 品牌无品牌、B、A、C单量分别为 238、79、75、58 无品牌 为渠道头部 可为主推款
- 品牌A、B的毛利贡献是 3942.0449、3595.1589 所以A可为利润款
- 所以主推款可以为无品牌 利润款为A B的退货高 少推B

#### 抖音
- 贡献为负 投停
- 货盘：单量<30 单量过小不做判断 

#### 京东
- 贡献为负 投停
- 货盘：单量<30 单量过小不做判断 

#### 微信
- 属于私域不做投放
- 货盘：
- 微信单量>30
- 品牌A、B、C单量分别为 80、77/74 BC 相差不大 可并列最高
- 所以主推款可以为品牌ABC

### 建议
- 淘宝：降低投放预算；搜索词、主图、活动给品牌 C、B；A 做高毛利搭配；无品牌不占首页。
- 拼多多：保持原预算：主铺无品牌走量、清季；A 少量带；B 退货高，少推。不要把淘宝品牌款搬去打价格。
- 微信：发券、群、复购券轮推品牌 A/B/C；无品牌可稍带。

SQL：`sql/02_channel/channel_ROI_brand.sql`

## 3. RFM 用户分层

### 结论  
普通客户约占 81% 人、74% 金额；重要保持约占 15% 人、17% 金额；VIP 约占 4% 人、9% 金额。

### 证据 / 做法  
- 口径：2025-12-17～2026-03-17，`payment_status = 'paid'`，时间用 `order_time` 
R：最近一次购买距截止日天数（阈值分高/中/低）  
F：90 天内订单次数（阈值分高/中/低）  
M：按销售额从高到低累计贡献切分（累计约 80% 的金额为高，约 95% 为中）

中间对 M 试过均值、2 倍、分箱，终版用累计贡献，再用各标签的人数占比对金额占比做验证。

### 建议  
看分层时同时看人数和金额，不要只根据标签名称判断。后续运营按人群定优先级：

- VIP（约 4% 人、9% 金额）：会员、新品、品牌款，走淘宝/微信私域，不靠加广告扩量
- 重要保持（约 15% 人、17% 金额）：最近还在买、买得不多、金额高，方向是维持、提高购买次数，可以优先做换季提醒、搭配、复购券
- 普通客户（约 81% 人、74% 金额）：人数最多、人均一般，仅在大促、清季时用活动覆盖
- 低价值（约 1% 人、0.3% 金额）：可忽略
- 重要发展、重要挽留：本窗无人，不做成大规模提客单或召回

SQL：`sql/03_rfm/rfm_90d.sql`

## 4. 转化漏斗

### 结论
支付已经较高，卡在前两步。浏览→加购约 35.9%，加购→下单约 43.7%，下单→支付约 83.0%。

### 证据 / 做法
- 用户级漏斗：行为在浏览之后且间隔 ≤7 天，路径为浏览→加购→下单→支付
- 窗口与渠道、RFM 对齐：2025-12-17～2026-03-17，支付状态为 `paid`
- 支付约 83%，与服饰常见 80%+ 一致，不是最大缺口

### 建议
- 商品页、主图、尺码与评价：对应淘宝主推品牌 C、B，微信私域推品牌 A、B、C
- 加购后促下单：券、凑单、发货说明
- 支付环节保持即可
- 不通过加投放来修漏斗；投放仍停抖音、京东，淘宝降费。

SQL：`sql/04_funnel/conversion_funnel.sql`

## 5. FineBI 渠道与用户看板
搭建渠道与用户看板，合并渠道支付用户、窗内复购、周趋势、月度支付用户数与设备

### 结论
- 渠道质量不能只看拉新：微信人少、复购高；淘宝、拼多多量大、复购一般
- 周趋势能看见春节，月度支付用户数按月看不出
- 京东、抖音个位数且窗内无人复购，和停投一致
- 替代原每周 4 小时的手工统计

### 证据 / 做法
- 指标卡：支付用户 1009、支付订单 1262、窗内复购率约 20.7%
- 周趋势：GMV 折线；标春节前夕、春节期间；2025-12-15、2026-03-16 两周是残周
- 渠道柱：支付用户数 vs 复购；柱顶复购率微信 34%、拼多多 20%、淘宝 17%、京东和抖音 0
- 月度支付用户数 + 设备：2025-12 残月 192、2026-01 425、2026-02 349、2026-03 残月 231；APP 约 69%、PC 约 19%、H5 约 12%

### 建议

- 春节当周掉量按节假日解释；读周趋势先认残周
-  看渠道要把支付用户数和复购一起看
