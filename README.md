# 电商全链路 SQL 分析（指标体系 / LTV / RFM / 漏斗）

导师带领的商业实战项目。基于电商数仓表结构，用 MySQL 完成指标口径统一、渠道×品牌 LTV、RFM 分层和交易漏斗分析，并用 FineBI 做用户增长与留存看板。

> 本仓库不包含业务数据，也不包含数据库账号。结论数字来自导师项目一次跑数。

## 业务问题

- 渠道价值缺少统一口径
- 高价值用户识别较粗
- 转化流失环节不明确
- 大规模获客后留存波动（流量稀释）需要验证

## 我做了什么

1. **指标层**：用户 / 商品 / 销售 / 履约 / 支付，统一 90 天窗口
2. **观测型 LTV**：渠道 × 品牌，`客单价 × 毛利率 × 人均购买频次 × 渠道转化率`
3. **RFM**：90 天 R/F 阈值 + M 按销售额累计贡献切分，输出 VIP / 保持 / 挽留等标签
4. **漏斗**：浏览 → 加购 → 下单 → 支付（7 日归因）
5. **FineBI**：渠道新增与留存、春节节点、新增规模 vs 次日留存、月活与设备结构

## 关键结论（90 天，截止 2026-03-17）

| 模块 | 结论 |
| --- | --- |
| LTV | 最高：官网 × 品牌 A（6833）；最低：官网 × 无品牌（3015），约 **2.3 倍**。无品牌组合整体垫底 |
| RFM | **VIP 占用户 20.93%，贡献销售额 43.17%** |
| 漏斗 | 浏览→加购 21.0%；加购→下单 24.9%；下单→支付 **82.3%**。瓶颈在前两步，不在支付 |
| 看板 | 抖音 90 天新增最高；需结合留存看渠道质量；设备以 APP 为主 |
